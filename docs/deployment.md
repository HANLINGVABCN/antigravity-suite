# 部署、反代与升级

## 普通 Ubuntu/Debian VPS（systemd）

要求 Linux x86_64 或 ARM64、Python 3.9+、curl、Xvfb、xdpyinfo 和本体运行依赖。Debian/Ubuntu 主机和容器使用同一脚本，自动选择服务管理方式：

```bash
git clone https://github.com/HANLINGVABCN/antigravity-suite.git
cd antigravity-suite
sudo bash install.sh
```

默认路径：

| 项目 | 路径 |
|---|---|
| 源码 | `/opt/antigravity-suite-improved` |
| 私有数据 | `/var/lib/antigravity-suite-improved` |
| 首次密码 | 数据目录内的 `initial-credentials.txt`，权限 600 |
| 服务 | `antigravity-suite-improved.service` |
| 默认监听 | `127.0.0.1:18888` |

`sudo bash install.sh` 会先显示终端安装向导，选项确定后才停止原服务、备份并安装。首次可选择后台端口、管理员用户名，以及随机或自定义密码。用户名使用 1–64 个英文字母、数字或 `._@-`；自定义密码为 12–1024 个字符，隐藏输入并二次确认，不保存明文。随机密码写入上表的私有文件，可用 `sudo cat` 查看；安装日志不打印密码。

检测到已有配置时，默认保留设置升级，也可选择仅调整监听端口；管理员密码、验证器、会话设置、档案 ID 和节点绑定保留。向导不会提供重置旧账号的入口，账号密码和验证器在网页“服务设置”中修改。旧首次凭据文件可能已失效，升级后应继续使用当前密码。配置损坏或数据存在但主配置丢失时拒绝初始化，需恢复私有备份。

自动化安装需明确使用 `sudo bash install.sh --non-interactive`：首次默认端口 `18888`、用户名 `admin`、随机密码；升级保留原设置。没有交互终端且未指定该选项时会提示用法并退出。`bash install.sh --help` 可查看说明。选好后会检查端口是否可用，占用或绑定失败时停止安装，并恢复原管理服务。安装结果包含实际地址、用户名及密码获取方式；服务正在运行且后台通过 HTTP 启动检查后才报告成功。安装器仅安装管理后台，本体仍通过网页安装按钮管理。

### 正在运行的反重力与配置独占锁

v0.9.3 在安装向导前先检查实际的原生反重力进程，显示 PID、用户与配置目录，说明运行中的客户端可能持有数据库、配置或本体资源独占锁。终端询问“是否关闭以上反重力，继续安装？[y/N]”。选择 n 或回车则明确取消，尚不停止任何程序，也不应用安装设置。

选择 y 后，依赖准备完毕再正常停止现有管理后台，让它先保存当前配置；随后关闭已确认的原生实例，等待进程停止，安装前再次检查。关闭客户端不调用原生退出登录、不删除登录文件或聊天记录。请先保存尚未保存的编辑内容。

非交互运行发现客户端仍在运行时，默认失败并提示自行关闭，或使用 `sudo bash install.sh --non-interactive --close-antigravity` 明确允许关闭。依赖准备期间出现其他未确认配置目录的原生实例、或进程被其他管理器重新启动时会停止安装并明确报错，避免边运行边改文件。

安装任何阶段失败都会显示阶段名称及退出码，上方保留具体错误。源码和服务恢复备份沿用原流程；安装器不会通过删除配置锁文件来绕过仍在运行的客户端。

本体未安装时仍可登录管理大厅、配置代理及导入档案。已有本体时顶部显示“卸载反重力”，未发现可用本体时显示“安装反重力”；安装从官方 HTTPS 地址下载并独立解包，默认版本固定为 2.29.0。配置 `core_deb_sha256` 或 `core_deb_sha512` 可验证供应方校验值。`dpkg-deb` 不会安装缺失的系统运行依赖；缺库时先补齐依赖。

项目会优先发现现有可用本体和原配置，后台以“已有共享配置”显示。确认卸载时只处理可验证的独立本体目录，移动到私有备份，保留配置和聊天库；无法安全确认的目录拒绝自动卸载。详见 [已有本体与配置](existing-installations.md)。

## Supervisor / s6 容器直接安装

同样运行 `sudo bash install.sh`，不再因缺少 systemd 拒绝安装。

- 已运行的 Supervisor：识别 `/config/keepalive/supervisord.conf`、`/etc/supervisor/supervisord.conf` 等本机配置。已有本项目服务时复用其源码、数据目录和身份，仅停止／更新本项目，不影响其他程序。
- 无 Supervisor：安装运行依赖并创建独立 Supervisor，配置和启动脚本保存在数据目录的 `supervisor/` 下，控制接口使用权限 600 的本机 Unix socket。LinuxServer s6 容器会登记 `/custom-cont-init.d` 启动钩子；其他容器显示 `sh 数据目录/supervisor/start.sh`，将其加入容器启动命令。
- 有 `/config` 的新容器默认把源码和数据放在 `/config/antigravity-suite-improved` 及其 `data/`；已有服务优先使用已经登记的实际路径。没有 `/config` 则使用上表默认路径。
- 重建容器时需持久化源码、数据和 Supervisor 或 s6 启动配置。安装脚本能在当前容器启动服务，但不能替宿主机修改 Docker 挂载或容器重启策略。

自定义位置可用 `sudo env ANTIGRAVITY_INSTALL_DIR=/明确源码目录 ANTIGRAVITY_SUITE_DATA=/明确数据目录 bash install.sh`。只有明确的绝对路径可接受，源码不能位于数据目录内；若与已运行服务的目录冲突则拒绝另建重复后台。`ANTIGRAVITY_SUPERVISOR_CONFIG` 可指定实际 Supervisor 主配置。

依赖准备后才停止已有后台，升级前保存私有数据及源码备份；启动失败恢复原源码和服务。安装结果只有通过 HTTP 检查后才报告后台已启动。

## 手动部署

安装依赖后建立独立环境：

```bash
cd /path/to/antigravity-suite
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
python3 configure_install.py --data-dir /path/to/private-data
ANTIGRAVITY_SUITE_DATA=/path/to/private-data .venv/bin/python server.py
```

配置向导只依赖 Python 标准库，可单独用于手动部署；首次选端口、用户名和密码，已有配置默认保留。随后验证前台启动，再参考 [Supervisor 示例](../examples/supervisor.conf) 加入你的监管配置。通常直接使用安装脚本即可完成容器部署。

服务用户必须能够读写数据目录、启动 Xvfb 并执行本体。默认 systemd 安装器使用 root；容器或手动部署可以选择专用普通用户。

## SSH 本地转发

在本地电脑运行：

```bash
ssh -N -L 127.0.0.1:19088:127.0.0.1:18888 -p 22 user@your-vps.example
```

然后访问 `http://localhost:19088/?portal=1`。在 VPS 虚拟桌面里的浏览器直接访问 `http://localhost:18888/?portal=1`。两处 localhost 分别指各自的机器。

## HTTPS 反向代理

使用独立域名。保留原始 Host、WebSocket 升级和长连接；关闭响应缓冲，设置足够长的读取超时。参考：

- [Nginx](../examples/nginx.conf)：需替换域名和证书路径。
- [Caddy](../examples/Caddyfile)：需替换域名，并满足自动证书签发条件。

本机 HTTPS 反代设置 `X-Forwarded-Proto` 时，可在私有 `config.json` 设置 `trusted_proxy: true`，用于 Secure Cookie 判断。该设置只信任 loopback 连接的转发协议头，不代表信任公网任意请求头。

不要直接公开原生动态端口或可选 TCP forwarder。管理员门禁由套件的 18888 网关提供。

## 升级与迁移

安装脚本先读取安装选项，默认保留当前配置，再停止自己的服务、备份数据、复制新源码和安装依赖。即使在选择后又修改了密码，升级应用选项时也会重新读取并保留最新凭据；如果端口同时被另一处修改，要求重新选择，避免覆盖。建议另行保存源码版本及完整数据备份。备份中包含凭据和聊天记录。

将早期单 HOME 数据迁移到独立 HOME / 共享历史库之前，使用 [迁移工具](../tools/migrate_shared_history.py)：

```bash
sudo systemctl stop antigravity-suite-improved
ANTIGRAVITY_SUITE_DATA=/var/lib/antigravity-suite-improved \
  /opt/antigravity-suite-improved/.venv/bin/python tools/migrate_shared_history.py
sudo systemctl start antigravity-suite-improved
```

迁移工具要求相关引擎都已停止，先备份，合并正文与索引，再链接各配置 HOME。不会尝试读取其他用户或其他应用的数据目录。

## 排错

```bash
systemctl status antigravity-suite-improved
journalctl -u antigravity-suite-improved -f
```

引擎日志位于 `profiles/<id>/home/engine.log`。诊断卡片分为尚未检测、检测中、正常和异常，原因以“可能是……”呈现。

- 登录回到门禁：检查 Cookie、HTTPS 及反代 Host。
- 启动任务不进入：设计上需等待按钮变为“进入”，再点一次。
- 代理检查失败：检查节点地址、协议、认证和网络。
- Google 鉴权失败：检查 OAuth 配置、凭据、账号资格及原生日志；有 Token 不等于有服务权限。
- 检测等待：卡片会显示代理检查、引擎启动、读取登录或等待 Google 权限响应及耗时。暂时超时或引擎端口变化会自动短暂重试，失败保留具体阶段；“暂未确认账号是否可用”不等于节点或账号必定失效。
- 导入等待：显示上传百分比及检查／保存阶段，处理中提示不定时隐藏。预检查只读取必要元数据，实际保存仍需解压和合并聊天库；实际耗时取决于上传网络、包内文件和服务器资源。
- 共享历史不可用：停止引擎后检查符号链接和索引版本，再从备份恢复。

卸载脚本取消管理服务并恢复已安装的原生退出保护，保留源码、账号、历史和备份。容器手动卸载及恢复方法见 [登录存档](login-sessions.md)。请勿直接递归删除数据目录。


## 配置与节点的固定身份

每个配置和代理节点在创建时生成固定 ID。名称、邮箱、地址、端口、协议、认证信息及代理绑定属于可编辑字段；普通编辑不会生成新对象，不改变原 ID、创建时间或存储位置。

代理卡片的“详情与编辑”展示固定 ID、创建/更新时间及绑定配置，支持手动修改或用一个节点链接替换连接参数。编辑时密码留空保持原值，点击“查看已保存密码”可查看，勾选“清除已保存密码”才会清除；不要把真实密码粘贴到公开问题报告。

节点连接被当前 IDE 使用时，允许改备注名称；修改地址、协议或认证前需先停止 IDE，以免正在运行的引擎继续使用旧连接。保存后原配置仍绑定同一节点 ID，下次启动使用新连接。未运行的绑定配置也无需重新绑定。

节点批量导入以及配置导入副本会创建新对象，因此各自生成新 ID；这与修改现有对象不同。删除后重新创建也会得到新 ID。API 不提供重命名 ID 的操作。


### 节点链接与字段一致性

打开节点编辑时，链接框自动显示由当前已保存字段生成的完整链接，可复制或修改，链接可能包含节点密码，请勿公开分享。**只修改节点名称时，会同步尚未手动修改的链接备注，连接和认证不变，可以直接保存。** 如果主动修改了链接中的备注，仍需与名称一致。链接和下方连接字段都填写时，协议、地址、端口、用户名、密码必须一致，否则在弹窗内显示冲突项并拒绝保存；不会覆盖原节点或改变 ID。只修改下方连接字段时可清空链接。编辑密码留空仍代表保留原密码，比较时使用已保存的密码；清除密码需要同时修改链接，或先清空链接。批量导入链接时请清空下方字段。

网页状态栏和操作按钮分行布局，短窗口及手机下列表自动调整；长弹窗只滚动内容区，标题、关闭和保存按钮保持可见。打开文件编辑时暂时隐藏档案详情，保存或取消后返回原窗口并保留尚未保存的档案输入；后台刷新不会清空弹窗中的输入。


## 导出和导入对应代理

v0.9.2 导出本工具格式时提供两个独立选项，默认都不勾选：“导出本地全部聊天记录”和“导出对应代理”。前者包含这台机器共享库的全部账号对话正文、过程文件和索引，导入后会合并到目标机器；取消时也过滤存档 `store` 和配置 `home` 中相同的聊天路径，避免顺带带入记录。工作区源码、账号凭据和其他配置仍可包含。旧客户端未发送新选项时，API 保持旧的含聊天记录导出行为。

点击档案的“导出”后，如果档案绑定了有效节点，可选择“导出对应代理”。勾选时，包内添加独立的 `profile/proxy.json`，只包含对应的一个节点及其认证信息；不勾选则不添加代理文件。整个代理池不会被打包。没有绑定节点时显示“无对应代理”。

选择配置包后，服务先检查包结构。若存在有效代理文件，显示“导入对应代理”选项，可取消勾选后只导入配置；如果没有代理文件，显示“无代理文件”，直接导入配置，不询问是否导入代理。旧格式档案包也适用这一流程。选择导入代理时会自动绑定；不导入时不会按旧 proxy_id 误绑定本地节点。

代理 ID 在目标服务器未被使用时可保留；ID 与内容相同的已有节点直接复用，ID 相同但连接内容不同则新建节点并为新档案绑定，避免改写现有节点。配置导入仍创建副本，已有配置 ID 和绑定关系不变。导入预览与管理员会话绑定，10 分钟后失效，取消时删除临时上传包。

附带代理的包包含节点密码；所有配置包本身包含账号凭据，应作为私有备份保管。

勾选聊天记录时包才包含共享对话库；没有勾选仍包含账号凭据。CPA／Sub2API 只导出账号凭据，没有聊天或代理选项。

## 网页重启后台服务

在“服务设置”保存端口后，点击“重启后台服务”使新端口生效。工作进程独立运行，先由服务正常停止保存当前配置，再重启 systemd／Supervisor 后台并检查实际监听端口。它与“启动反重力”“停止反重力”以及原生引擎重启是不同操作。

后台会短暂断开；同端口页面等待恢复并刷新。直接通过端口访问时提示新地址；反代或 SSH 转发需同步改目标端口。尚未保存的表单不会自动提交，端口占用会阻止重启。新端口启动失败时尝试恢复原端口，异常提示保留；账号密码、验证器和配置节点不重置。


## 可选的验证器两步验证

在网页“服务设置”中可以自行绑定、开启和关闭验证器。初始状态关闭，升级保留原设置。开启流程、恢复码和手机丢失处理见 [验证器说明](authenticator.md)。


## CPA / Sub2API 账号文件

导入和导出现在都提供三个格式入口。CPA/Sub2API 只转换 Antigravity 账号凭据，忽略第三方代理；本工具原生配置包仍提供可选代理导入导出。完整字段、过滤及兼容限制见 [格式兼容说明](transfer-formats.md)。

自动发现和共享原配置、运行实例接管、容器进程权限及切换影响见 [已有本体与配置](existing-installations.md)。发现阶段不覆盖原 Token；原生登录后后台识别对应的固定配置。


## 网页自动更新

安装含更新入口的版本后，顶部“更新项目”可以检查并升级 GitHub 正式版；无需再敲升级命令。此前没有更新入口的旧部署需先按上述步骤更新一次。自动升级只管理自己的服务，保留当前账号、节点和数据，并准备私有恢复备份，详见 [自动更新](automatic-updates.md)。
