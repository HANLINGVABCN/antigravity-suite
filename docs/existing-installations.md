# 发现已有反重力并共用配置

服务启动及后台刷新时，会先查找**已有的可用本体与配置**，不将桌面图标作为特殊优先入口，也不会只检查套件自己安装的路径。

## 本体发现

扫描包括正在运行的 Antigravity、配置指定路径、常见安装目录和 PATH 中的命令。检查可执行权限、资源目录、Linux 架构及可检查的运行库；只有找到可用本体，顶部按钮才显示 **卸载反重力**，否则显示 **安装反重力**。

发现现有可用的独立本体后，项目直接使用它，不再复制第二套本体。卸载时停止对应实例，将独立本体目录移到私有备份中，保留配置、账号与聊天记录；非独立或无法安全确认的应用目录会拒绝自动卸载。包管理器的安装记录不会因此自动删除，后续重新安装时会使用已记录的本体目录。

## 部署时导入已有登录

首次部署或接管时，读取已有反重力的登录文件。包含可续期登录凭据时，将登录和配置快照提取为**普通账号配置**，命名为 **默认配置-机器名**，与网页登录、导入的其他账号采用相同卡片和操作；没有登录的新部署，配置列表为空，不创建占位卡片。机器名默认取系统主机名，也可由部署配置中的 `machine_name` 提供。

- 已有相同账号时复用原卡片，名称、ID、创建时间和代理绑定保持不变，不添加运行目录的重复卡片。
- 登录和配置文件以私有快照保存；桌面仍运行时，用 SQLite 备份读取已提交的数据库/WAL 状态，原目录不被此次提取覆盖。
- 提取只执行一次；后续本体和进程检查不持续生成账号。删除账号后，重启也不会重新导入它。
- 运行目录单独登记在后台，不在账号列表显示特殊标签、目录卡片或特殊边框。
- 旧版本重复的运行目录条目不再显示，原身份和文件保留在私有数据中；独立的已登录旧条目转换为普通账号时保留原 ID。

桌面和网页继续使用同一份当前运行配置。切换先保存当前账号存档，再载入所选账号；原目录的新凭据仍是当前账号的有效运行数据，重启不拿旧快照覆盖。账号存档和节点绑定保留。

## 实例接管

通过 PID、进程启动时间、实际用户、HOME / 配置目录及所属监听端口识别实例。匹配的原生实例可以接管；启动、切换和关闭时只处理对应进程与后代，不全局 pkill，不终止桌面会话的公共进程组。

部分容器限制跨用户读取 `/proc/exe` 和环境；此时使用可读取的命令身份与系统账号目录辅助识别，以配置所属用户核对端口。仍然无法匹配时不会把别的端口当作就绪。

接管后，切换账号或“停止 IDE”可能关闭原生窗口；管理服务停止时也会停止它当前接管的实例。再次打开原生反重力或在后台启动仍读取原目录，不需要重建配置。副本测试进程不应与同一配置同时运行，以免配置锁或数据库冲突。

## 限制和排错

- 需要访问安装路径、配置目录与进程信息。普通服务用户不能接管其他用户的私有配置，后台会显示不可接管。
- 定制安装路径、配置目录或环境在自动识别失败时仍需明确配置，不保证任意第三方封装都能识别。
- “已安装 / 可用本体”表示找到可运行环境，不表示 Google 账号有权限；登录仍由检测结果和原生 Google 响应决定。
- 安装状态与配置卡片可能有数秒刷新延迟。点击本体管理时会再次扫描。
- 管理服务原先独立运行而残留的实例，需要按准确 HOME / 进程身份清理；升级前保存完整私有数据备份。

账号存档仍独立，只把当前所选账号载入原运行配置，不向所有存档同步同一个 Token。账号切换会停止相关实例；正在使用的原运行目录使用原所属用户和显示环境，桌面原图标无需改动。该运行模式让两个入口一致，但当前使用者都能看到所选账号的数据，不提供多个桌面用户之间的隔离。
