# 登录存档与退出配置

## 每次登录保存一个配置

部署时已有的登录只提取一次，普通卡片名为“默认配置-机器名”。部署后每次**成功重新登录**都新增一个配置，包括同一个邮箱的再次登录。配置默认命名为“邮箱 · 登录 N”，创建后可以改名或绑定节点，ID 始终不变。

程序同时记录登录操作编号与凭据哈希。不能仅凭整个文件的哈希变化判断新登录：正常续期也会改变文件，否则配置列表会不断增长。兼容客户端的登录开始和成功回调用于区分新登录，哈希用于识别重复读取和当前会话的凭据更新。

| 操作 | 配置列表 |
|---|---|
| 再次成功登录同一邮箱 | 新建一个配置，旧配置保留 |
| 成功登录不同邮箱 | 新建一个配置，旧配置保留 |
| 当前会话的访问令牌续期 | 更新当前配置的凭据，不新增 |
| 从面板切换到已有配置 | 载入原 ID，不新增 |
| 点击“停止 IDE”或重启服务 | 保存当前配置，不计作重新登录 |
| 登录取消或失败 | 不创建成功登录的存档 |

后台每 3 秒检查当前工作环境，普通变化需连续稳定读到后才处理。成功回调会立即尝试保存；如果文件仍在写入，后续扫描再重试。旧账号卡片不会直接改成另一个账号，同邮箱的旧会话也不会被新登录覆盖。

## 退出配置

网页顶部和桌面／网页悬浮面板都提供“退出配置”。它依次停止当前引擎，保存登录存档，备份并移除**当前工作环境**的登录文件，然后重新打开反重力登录界面。已保存的配置和共享聊天记录保留，不向 Google 发送撤销授权请求。

退出后网页显示未登录状态，可点击“进入登录界面”完成新登录，也可选旧配置“切换并启动”，等待完成后“进入”。管理服务重启后保持等待登录，不自动把默认账号恢复回来。“停止 IDE”仅停止并保存；“退出后台”仅退出管理网页。

清理后会调用原生只读接口确认当前环境没有登录 Token。无法确认时退出显示异常及可能原因，并尝试恢复退出前的状态；原存档和退出备份保留。工作目录与存档目录分开，没有外部原配置时使用 `data/login-environment/home`，不会通过删除存档 HOME 来退出。

## 原生退出保护

兼容的 Linux Electron 客户端会安装可恢复的本体保护。升级时先停止被接管的实例、保存当前配置，再更新保护并重启。安装路径需要写权限；不兼容入口或未验证的客户端不会被误报为保护已完整生效。网页会显示“已安装，等待客户端验证”或“桌面退出保护已验证”。

原生“退出登录”在改变认证状态之前被拦截，弹窗提示：

> 退出登录可能使已保存的登录凭据失效。请返回配置面板，使用“退出配置”。

网页网关和原生请求层也拒绝 `AuthLogout`，避免绕过按钮直接提交该接口。其他插件和管理后台自己的登出不在拦截范围。原生弹窗使用客户端页面实现，避免受限桌面容器的 GTK 系统弹窗错误。

原本体资源备份保存到 `data/desktop-guard-backups`，不会提交到公开仓库。仅本体更新、手工修改或未来版本差异可能使保护不再兼容；遇到“等待验证”或错误时请通过面板退出，并保留备份排查。

## 恢复原生退出与卸载

卸载本体前会恢复原资源，再将本体移到备份。卸载管理服务的脚本也会恢复保护。容器手动卸载时，先停止管理服务和使用同一本体的反重力实例，再运行：

```bash
ANTIGRAVITY_SUITE_DATA=/你的私有数据目录 \
  /你的项目目录/.venv/bin/python /你的项目目录/desktop_guard.py --restore
```

恢复前核对当前资源和原备份的哈希；如果本体已发生其他修改，会拒绝覆盖。需要保留原备份并按实际版本处理，不能直接拿旧资源替换任意新版客户端。

## 使用边界

多个登录存档可能来自同一份 Google 授权，保存为不同配置不等于 Google 为每个文件提供独立授权，也不保证永远有效。外部撤销授权、修改账号安全设置或服务端失效仍可能影响多个存档，检测结果才反映当前可用性。

桌面控制连接只监听本机，使用每次管理服务启动生成的能力令牌；仅允许查看精简状态、切换、重启、退出配置和记录登录。它不分享后台密码、验证器或管理员会话，也不提供导出凭据、编辑任意文件或执行任意命令的接口。系统用户之间的权限隔离及网络出口限制仍见 [隐私说明](privacy.md)。
